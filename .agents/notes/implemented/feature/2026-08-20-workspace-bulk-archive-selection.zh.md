# Agent Note: 工作区批量归档选择

Status: implemented

[English](2026-08-20-workspace-bulk-archive-selection.md) | 中文

## 问题

归档单个 Session 需要精确操作对应行，对多个 Session 重复操作效率很低。批量操作必须以用户当前可见列表作为选择依据，排除临时空白 Session，并在请求失败时保留可恢复状态，明确显示需要重试的项目。

## 决策

**工作区标题栏通过归档箱图标提供批量选择入口。** 批量模式用复选框替换每个非空白 Session 行的状态与尾部操作。批量模式结束前，会话打开、拖动、右键菜单和悬停卡片均被禁用。空白行继续显示，但不可选择。

**选择遵循当前实际渲染的 Session 顺序。** 单击切换一个 Session；Shift 单击从最近锚点到目标，按当前可见顺序加入首尾均包含的范围。折叠、过滤或其他投影变化会从选择中移除不可见 id；分组方式与未读过滤变化会清空选择；开始搜索会退出批量模式。

**底部工具栏拥有完整的批量操作。** 工具栏显示已选数量，可选择或清除可见行、取消批量模式，并通过行内二次点击按钮执行归档。会话行归档按钮使用相同模式；失焦或 Escape 会取消待确认状态，不打开弹出层。

**批量归档并发调用现有操作。** Client 通过 `Promise.allSettled` 为每个已选 id 各调用一次 `archiveSession`。全部成功时退出批量模式；部分失败时仅保留被拒绝的 id，显示成功数与失败数，并保留工具栏供重试。该功能不引入新的 Host 操作或持久化格式。

## 曾考虑的替代方案

**确认弹出层。** 未采用，因为它让确认操作脱离发起控件，并为行操作和批量操作都增加指针移动。复用保持焦点的按钮可让第二次操作留在原位，并为失焦与 Escape 提供明确的取消路径。

**Host 批量归档 RPC。** 未采用，因为互相独立的现有请求已经具备所需的持久化与错误标识能力。`Promise.allSettled` 无需增加 wire 行为即可保留逐 Session 失败信息。

**部分失败后继续保留成功 id。** 未采用，因为这些请求已经完成；继续选中会让用户误以为它们仍需处理，也会使重试语义不清。

## 后果

批量选择是瞬态浏览器状态，仅跟随仍可见的可选择行。部分失败可在原处继续处理，全部成功则回到普通浏览。聚焦的行与 WorkspaceBrowser 测试覆盖确认取消、交互抑制、Shift 范围、可见性对账和部分失败；workspace-management e2e 通过批量模式覆盖持久归档全链路。
