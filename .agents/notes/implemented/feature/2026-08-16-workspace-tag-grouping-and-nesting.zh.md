# Agent Note: 工作区浏览器标签分组、等待嵌套与行右键菜单

Status: implemented

[English](2026-08-16-workspace-tag-grouping-and-nesting.md) | 中文

本决策部分被[独占分组与共享任务看板](2026-08-21-workspace-exclusive-groups-and-board.md)替代：多标签元数据与标签分组停止生效；等待父任务、拖拽中段嵌套和右键菜单继续有效。

## 问题

工作区浏览器只按 Host Workspace 对会话分组。跨目录组织依赖会话标题约定，任务之间无法表达一个任务正在等待另一个任务，行操作也隐藏在省略号按钮后。用户需要可配置的标签组、任务之间的等待关系，以及通过右键菜单直接访问行操作。

## 决策

**标签与等待关系是浏览器本地元数据，不写入会话日志。** `WorkspaceViewState` 在既有持久化键下存储 `sessionMeta: Record<sessionId, { tags?: string[]; parent?: string }>`，并用 `knownTags: string[]` 保存显式创建的空标签组。`deriveTagGroups` 只读取用户元数据；模型通过 `todo_write` 写入的标签不影响分组。`waitingOrder` 把子会话排在父会话之后并设置 `SessionNode.depth`；环中未放置的成员作为根节点放置。

**挂接与打标签都支持拖放和菜单路径。** 拖到会话行中间 30%–70% 的区域会把被拖会话挂到该任务下，上下边缘仍保留排序语义。把嵌套行拖到行间会解除挂接。在标签视图中，拖到标签标题会添加该标签，拖到未打标分组会清空标签；`ProjectRowItem` 接收并高亮 `dropTarget`。菜单保留“设置标签…”，挂接则保留为拖拽交互。

**会话行与工作区行共用右键菜单路径。** 两者都处理 `onContextMenu`、阻止浏览器菜单并打开行菜单。会话行在工作区已知时还提供“在此工作区新建会话”。

**`todo_write` 接受可选 `tags`。** `TodoItem` 包含 `tags?: string[]`；工具 schema、描述与投影都会保留该字段。写入时会去除首尾空白、空标签和重复标签，最多接受八个标签，每个标签最多 32 个字符。数据可供消费方使用，但工作区分组仍由用户管理。

## 曾考虑的替代方案

**从会话日志中的 `TodoItem.tags` 派生工作区分组。** 未采用，因为模型生成的标签会产生无意的分组，而且客户端无法安全追加会话事件。浏览器本地元数据无需改变 Host，就能表示明确的用户组织意图。

**构建独立的目录式依赖树。** 未采用，因为行中部挂接与嵌套行可以扩展既有行模型，而另一棵树会重复其渲染与交互结构。

## 后果

工作区组织会在本地持久化，并与回放的模型输出保持独立。用户可以在不改变会话日志语义的情况下对会话分组并表达等待关系，但这些关系不会通过 Host 同步，模型写入的 todo 标签也不会重新组织浏览器。
